## 1. Executive Summary

This remediation report verifies the successful implementation of task **T01.3-R1: Secure Razorpay Refund Webhook Processing**.

During the preceding T01.3 security audit, two security weaknesses were identified:
1. **FINDING HIGH-01:** Razorpay refund webhook events (`refund.processed` and `refund.failed`) were marked as `IGNORED` in `WebhookService`, leaving asynchronous refunds unconfirmed and balances out-of-sync when the payment gateway took longer than immediate synchronous timeout windows.
2. **FINDING MED-01:** In `PaymentsRepository.settleRefundBalance` and `PaymentsRepository.releaseRefundBalance`, balance adjustments read the payment document into memory, calculated `cumulativeRefundedPaise` and `pendingRefundPaise` arithmetic in Node.js runtime memory, and executed an unconditional `$set`. This introduced a concurrency race condition where concurrent settlements or releases could overwrite concurrent updates.

Both findings have been completely remediated, hardened with atomic MongoDB aggregation pipelines and conditional transitions, backed by comprehensive idempotency mechanisms, zero-phantom-inventory safeguards, and verified by 20 new adversarial integration tests (Tests 51–70 in `server/src/tests/payment-lifecycle.test.ts`).

## 2. Remediated Architecture & Technical Implementation

### A. FINDING HIGH-01: Razorpay Refund Webhook Event Processing
- **File:** `server/src/modules/payments/webhook.service.ts`
- **Signature & Payload Verification:**
  - Preserves HMAC-SHA256 signature verification over raw incoming payload using `IPaymentProvider.verifyWebhookSignature`.
  - Computes payload SHA-256 hash and validates `x-razorpay-event-id` or deterministic `evt_${payloadHash.slice(0, 16)}` fallback.
  - Webhook event deduplication checks `PaymentWebhookEventModel` before processing; duplicate events return `{ status: 'ALREADY_PROCESSED' }` without re-executing balance mutations.
- **Entity Extraction & Multi-Tier Resolution:**
  - Extracts provider refund ID, provider payment ID, order ID, amount, and currency from both `payload.payload?.refund?.entity` and `payload.payload?.payment?.entity`.
  - Multi-tier refund lookup resolves `IRefundLean`:
    1. By `providerRefundId` (`RefundModel.findOne({ providerRefundId })`).
    2. By `refundReference` via `notes.refundReference` or `receipt.replace(/^rcpt_/, '')`.
    3. Fallback by `paymentId` matching a `PENDING` or `PROCESSING` refund with matching paise amount.
- **Validation Guards:**
  - Rejects unknown provider refund IDs with `REFUND_NOT_FOUND`.
  - Rejects payment mismatches (`providerPaymentId !== payment.providerPaymentId`) with `PAYMENT_MISMATCH`.
  - Rejects amount discrepancies (`webhookAmount !== refund.amountPaise`) with `AMOUNT_MISMATCH`.
  - Rejects currency discrepancies (`webhookCurrency !== payment.currency`) with `CURRENCY_MISMATCH`.
- **Atomic State Transitions & Conflict Defense:**
  - Invokes `transitionRefundStatus` to conditionally advance only `PENDING` or `PROCESSING` refunds to `PROCESSED` or `FAILED`.
  - If a duplicate or concurrent webhook arrives, `transitionRefundStatus` returns `null`:
    - If already in target status, returns idempotent `ALREADY_PROCESSED` or `ALREADY_FAILED`.
    - If in conflicting terminal state (e.g., `refund.failed` received for an already `PROCESSED` refund), rejects with `CONFLICT` status without downgrading or releasing balances.
- **Booking Cancellation & Zero Phantom Inventory:**
  - Upon full refund settlement, associated booking is transitioned to `CANCELLED`.
  - Associated inventory hold is inspected: only if `hold.status === CONSUMED` is `releaseHold` invoked to restore room inventory units. In late payment scenarios where hold was `EXPIRED`, inventory units are NOT restored twice, strictly preventing overcapacity creation.
- **Audit Logging & Guest Notifications:**
  - Emits immutable admin audit log entries (`ADMIN_AUDIT_ACTIONS.PAYMENT_REFUNDED`).
  - Publishes real-time tourist notifications (`NOTIFICATION_TYPES.PAYMENT_REFUNDED`).

### B. FINDING MED-01: Atomic MongoDB Balance Settlement & Release
- **File:** `server/src/modules/payments/payments.repository.ts`
- **Replaced In-Memory Read-Modify-Write with Atomic MongoDB Aggregation Pipelines:**
  - In `settleRefundBalance`:
    ```typescript
    const updatePipeline = [
      {
        $set: {
          cumulativeRefundedPaise: {
            $add: [{ $ifNull: ['$cumulativeRefundedPaise', 0] }, amountPaise],
          },
          pendingRefundPaise: {
            $max: [
              0,
              { $subtract: [{ $ifNull: ['$pendingRefundPaise', 0] }, amountPaise] },
            ],
          },
          refundAmountPaise: {
            $add: [{ $ifNull: ['$cumulativeRefundedPaise', 0] }, amountPaise],
          },
          refundId: latestRefundId,
          refundedAt: '$$NOW',
          updatedAt: '$$NOW',
          status: {
            $cond: [
              {
                $gte: [
                  { $add: [{ $ifNull: ['$cumulativeRefundedPaise', 0] }, amountPaise] },
                  '$amountPaise',
                ],
              },
              PAYMENT_STATUSES.REFUNDED,
              PAYMENT_STATUSES.CAPTURED,
            ],
          },
          reconciliationStatus: {
            $cond: [
              {
                $gte: [
                  { $add: [{ $ifNull: ['$cumulativeRefundedPaise', 0] }, amountPaise] },
                  '$amountPaise',
                ],
              },
              'REFUNDED',
              'PARTIALLY_REFUNDED',
            ],
          },
          ...(reason !== undefined && reason !== null ? { refundReason: reason } : {}),
        },
      },
    ];
    return PaymentModel.findByIdAndUpdate(paymentId, updatePipeline, { new: true, session });
    ```
  - In `releaseRefundBalance`:
    ```typescript
    const updatePipeline = [
      {
        $set: {
          pendingRefundPaise: {
            $max: [
              0,
              { $subtract: [{ $ifNull: ['$pendingRefundPaise', 0] }, amountPaise] },
            ],
          },
          status: {
            $cond: [
              { $gte: [{ $ifNull: ['$cumulativeRefundedPaise', 0] }, '$amountPaise'] },
              PAYMENT_STATUSES.REFUNDED,
              PAYMENT_STATUSES.CAPTURED,
            ],
          },
          updatedAt: '$$NOW',
        },
      },
    ];
    return PaymentModel.findByIdAndUpdate(paymentId, updatePipeline, { new: true, session });
    ```
- **Atomicity Guarantees:** Eliminates in-memory race conditions by calculating balance adjustments atomically in the database engine.
